# pdfnative-cli v1.5.0

<!-- GitHub Release title: v1.5.0 — typography, 27 scripts, CMYK & PDF/X-4 -->

_Released 2026-09-17_

Built on **pdfnative 1.8.0**. This release exposes every 1.8.0 engine feature — the
typography engine, CMYK colours and colour bars, PDF/X-4 output with a structural
validator, five more scripts (**27 Unicode scripts**) with `latin` aliases, custom fonts
from disk, and UTC, pinnable creation dates that make output **byte-reproducible** — and
delivers every roadmap item the engine unblocked. It also adopts the engine's engineering:
one quality gate, a byte-exact sample baseline, a PDF/A + PDF/X conformance corpus,
hardened CI with Trusted Publishing and attestations, a documentation verifier and a
committed Claude Code layer. 21 commands, 19 schema subjects and 12 stable error codes
are unchanged; the command surface is 100% backward-compatible.

## Highlights

- **Typography** — `layout.typography` (widows/orphans, keep-with-next, splittable
  paragraphs, justification, optical margins, soft hyphens, French punctuation spacing
  with unit binding, kerning, OpenType features, exact base-14 metrics) plus four flags:
  ```bash
  pdfnative render -i report.json -o report.pdf --font latin --lang latin \
    --split-paragraphs --keep-headings-with-next --kerning --font-features onum,liga
  ```
- **CMYK & PDF/X-4** — every colour accepts CMYK, printer's marks gain colour bars, and
  `render --pdfx pdfx4 --output-intent-icc press.icc --trapped false --strict` writes a
  PDF/X-4 file that `inspect --check pdfx` re-validates.
- **Reproducible output** — the global `--creation-date <iso8601>` (or
  `SOURCE_DATE_EPOCH`) pins `/CreationDate`, `xmp:CreateDate`, `{date}` and the trailer
  `/ID` in UTC: the same input renders to identical bytes on every host and timezone.
- **27 scripts & custom fonts** — `--font lo|nod|khb|tdd|cjm` (Lao, Tai Tham, New Tai
  Lue, Tai Le, Cham), `ha`/`yo`/`ig`/`sw` aliases of `latin`, `--font-file <path.ttf>[:name]`
  (validated, capped, never from a JSON payload); `--variant table` embeds fonts too.
- **Roadmap items delivered** — global flags before the command
  (`pdfnative --json --dry-run render …`), `annotate link`, `sign --timestamp-timeout`,
  a weak-digest note in `verify` (SHA-1 imprints refused under `--strict`),
  `inspect --iso-dates`, richer `doctor` checks, three more SSRF-blocked ranges, a size
  cap on `--layout`, CHANGELOG compare links.
- **Engineered like the engine** — `npm run gate` (fast / CI / publish, `--require-all`),
  a 79-sample byte/semantic baseline, a 16-file PDF/A + PDF/X corpus, `verify:docs`
  (25 rules over `docs/assets/ecosystem.json`), `release-prepare.ts`, hardened workflows
  (harden-runner, SHA pins, Trusted Publishing, SBOM + attestations, committed rulesets),
  `CLAUDE.md` = `@AGENTS.md` with a guard hook and a `/release-audit` skill.

## What's new

### render

- `layout.typography` passthrough (`widows`, `orphans`, `splitParagraphs`,
  `keepHeadingsWithNext`, `opticalMargins`, `punctuationSpacing: "fr" | "fr-CA" | rules[]`,
  `unitBinding`, `bindShortWords`, `hyphenationLanguage`, `kerning`, `fontFeatures`,
  `metrics`; soft hyphens U+00AD are honoured unconditionally — the engine's
  `TypographyOptions` keys verbatim), paragraph `align: "justify"`, block-level
  `keepWithNext` / `splittable`;
  `--split-paragraphs`, `--keep-headings-with-next`, `--kerning`, `--font-features <tag,…>`.
  Nested `typography` / `outputIntent` objects now merge one level deep between the
  document, `--layout` and the flags.
- CMYK colours (`"c m y k"` 0–1 or `[c,m,y,k]` percent) everywhere;
  `layout.print.marks.colourBars: true | { tints, size }`.
- `--pdfx pdfx4`, `--output-intent-icc <file.icc>` (16 MiB cap, `acsp` checked, merged into
  `layout.outputIntent`), `--output-intent-id <s>`, `--trapped true|false|unknown`.
  Pre-checks refuse `--pdfx` with PDF/A or encryption (exit 2); the engine's PDF/X and print
  coherence errors map to `E_INPUT`; `PDFX_NO_FONT_ENTRIES`, `PDFX_DEVICE_CMYK`,
  `PDFX_ANNOTATIONS` and `TYPOGRAPHY_FEATURE_INEFFECTIVE` join the `--strict` diagnostics
  (9 codes); the envelope carries `pdfx`.
- `--font` / `--lang`: `lo`, `nod`, `khb`, `tdd`, `cjm`; `ha`, `yo`, `ig`, `sw` → `latin`
  (31 bundled font modules / 27 scripts). `--font-file <path.ttf>[:name]` (repeatable):
  path check, 32 MiB cap, magic bytes, `parseFontData` + `validateFontData`, name from the
  file stem, added to `--lang`. `--variant table` embeds `--lang` fonts.
- `--layout` files and inline `layout` revive `creationDate` and `outputIntent.iccProfile`
  arrays; `--layout` files share the 50 MB cap.

### Global flags

- `--creation-date <iso8601>` (10th global flag; fallback `SOURCE_DATE_EPOCH`) pins the
  creation instant process-wide through `setDefaultCreationDate()` — `batch` tasks inherit
  it; the envelope carries `creationDate`; an invalid value is a usage error.
  `sign --signing-time` and `metadata --mod-date` stay separate; encrypted output is never
  reproducible.
- Global flags may precede the command name: `parseArgs` gained a boolean-flag table and
  `splitCommandArgv()` finds the command wherever the flags sit.

### inspect / annotate / sign / verify / doctor

- `inspect --pdfx` (validation report), `--check pdfx`, `pdfxConformance` (always present),
  `--iso-dates`; `--summary` adds `pdfx`; text report prints `PDF/X:` lines.
- `annotate` type `link` (`rect` + `url` — `http`, `https`, `mailto`; `E_INPUT` otherwise),
  emitted as a `/Link` + `/URI` action; CMYK colours accepted.
- `sign --timestamp-timeout <ms>` — bound on the TSA round-trip, reported as
  `timestamp.timeoutMs`.
- `verify` reports `timestampDigest`; a SHA-1 messageImprint adds
  `weak digest: RFC 3161 messageImprint uses SHA-1 (refused under --strict)` and fails
  under `--strict` (`E_VERIFY_FAILED`).
- `doctor` checks `fonts` (`31 modules / 27 scripts`, probed on disk), `unicode`
  (`USE_UNICODE_VERSION`) and `conformance` (`pdfa1b,pdfa2b,pdfa2u,pdfa3b,pdfx4`).

### Agent surface

- `schema`: `render` describes typography, `layout.pdfx`, CMYK and colour bars; `inspect`
  requires `pdfxConformance` and pins `pdfx`; `inspect-summary` requires `pdfx`; `status`
  pins `pdfx`, `creationDate`, `timestamp.timeoutMs`; `annotate` gains `link` + `url`;
  `verify` gains `timestampDigest`. Completions carry every new flag.
- `govern policy` prints the full 1.1.0 policy (`claude_code` block included), identical to

- The consumer contract moved to **`docs/AGENT_CONTRACT.md`** (from AGENTS.md, which now
  holds the repository rules for agents); `llms.txt` carries `Current version`, the 12

## Compatibility

- **100% backward-compatible command surface** — no flag, default, exit code or error code
  changed; every envelope field is additive and pinned by `schema status`. 21 commands,
  19 subjects, 12 codes; 10 global flags (was 9).
- **Inherited pdfnative 1.8.0 byte-level changes**: every date is written in UTC
  (`+00'00'`), `{date}` follows the pinned creation date, tagged output carries
  `/ActualText`, TrueType subsets carry hinting tables. Every PDF the CLI writes therefore
  differs byte-wise from 1.4.0 output while staying spec-valid; a consumer that hashed
  1.4.0 output must rebaseline once — and can now pin the bytes with `--creation-date`.
- `extract-text` / `compare` return the source text of tagged documents (`/ActualText`),
  not the shaped glyph string.
- `samples/run-all.js` is removed; `npm run build && npm run test:generate` (or
  `PDFNATIVE_CLI=… npm run test:generate` against a global install) replaces it.
- Encrypted output is never byte-reproducible; a signed file's incremental revision carries
  a per-revision `/ID` (upstream — see Notes).

## Security

- SSRF guard: benchmarking `198.18.0.0/15`, TEST-NET-1 `192.0.2.0/24` and NAT64
  `64:ff9b::/96` (and their IPv4-mapped forms) are refused.
- Bounded, validated binary inputs: `--layout` ≤ 50 MB, ICC ≤ 16 MiB with the `acsp`
  signature, fonts ≤ 32 MiB with magic-byte and parser validation; fonts and profiles are
  only ever loaded from command-line paths.
- `verify` surfaces SHA-1 timestamp imprints and refuses them under `--strict`.
- `annotate link` URLs go through `validateURL` and PDF-string escaping.
- Supply chain: Trusted Publishing (OIDC, npm ≥ 11.5.1), SBOM + build attestations,
  harden-runner and SHA-pinned actions on every job, `npm ci --ignore-scripts`, dependency
  review, weekly `npm audit`, committed rulesets, a HITL guard hook for agents.

## Fixed

- `pdfnative --json render …` no longer swallows the command name.
- `--layout` no longer replaces a nested `typography` / `outputIntent` object the document
  supplied when the file sets a sibling key.
- A test used a 128-byte fake ICC profile the 1.8.0 engine rejects; the suite now uses a
  real synthetic `prtr` CMYK profile (also shipped under `samples/render/print/`).

## Notes

- `inspect --check pdfx` uses pdfnative's structural validator — validation evidence, not a
  certified preflight. PDF/X and PDF/A cannot be claimed by the same file.
- **Upstream limits recorded in ROADMAP.md**: `metadata` rewrites the XMP without the
  PDF/X identification (re-check after editing); signed output carries a per-revision `/ID`
  drawn at signing time (signed samples are fingerprinted semantically); PDF/X-1a / -3 /
  -4p and spot colours are not exposed by the engine; hyphenation dictionaries from the CLI
  are deferred by posture.
- `punctuationSpacing: "fr"` inserts U+202F only where a font is embedded (`--font latin
  --lang latin`); `TYPOGRAPHY_FEATURE_INEFFECTIVE` reports a requested feature the font
  lacks (`tnum` on Noto Sans).
- The CI `eol-lf` rule warns on the CRLF blobs still in history; the maintainer's
  renormalisation commit (`git add --renormalize .`) will flip it to fail.

## Upgrade

No action required from 1.x — all existing invocations behave identically on Node ≥ 22.
Hash-based consumers: 1.8.0 changes the bytes of every PDF (UTC dates, `/ActualText`,
hinting tables) — rebaseline once, then pin with `--creation-date` / `SOURCE_DATE_EPOCH`.
Sample baseline: `tests/regression/baselines/samples.sha256.json` is created in this
release (79 entries, all `since: 1.5.0` — the 1.4.0 line had no determinism plumbing
to chain from); the conformance corpus grows from 12 to 16 files.
