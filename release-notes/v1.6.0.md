# pdfnative-cli v1.6.0

<!-- GitHub Release title: v1.6.0 — right-to-left, 32 scripts, spot colours & the dual PDF/A + PDF/X claim -->

_Released 2026-11-01_

Built on **pdfnative 1.9.0**. This release exposes every 1.9.0 engine feature — right-to-left
layout under the full Unicode Bidirectional Algorithm, five more Indic scripts (**32 Unicode
scripts**), spot colours, the **PDF/A-2 + PDF/X-4 dual claim**, JPEG 2000 images, four more
diagnostics, the stream-limit policy of `extractText()`, offline LTV material, engine-built
link bodies and text-string decoding — and delivers every roadmap item the engine unblocked.
It also aligns the repository's CI/CD with the engine's: the gate is a required check on
Ubuntu, Windows and macOS, the previous release's test suite and `schema` captures are
replayed on every pull request (a **compatibility promise** that is now a check), the
workflows are linted, CodeQL is hardened, the release pipeline is guard → build → publish →
attest, and ClusterFuzzLite fuzzes the CLI's own parsers. 21 commands, 19 schema subjects,
12 stable error codes and 10 global flags are unchanged; the command surface is 100 %
backward-compatible, and the byte changes inherited from the engine are listed in the
compatibility ledger below.

## Highlights

- **Right-to-left** — `render --direction auto|ltr|rtl` (or a per-paragraph `direction`)
  lays Arabic, Hebrew and mixed paragraphs out under UAX #9: right-aligned, justified in
  visual order, punctuation and numbers on the right side. `extract-text` returns them in
  **logical order** — from untagged output too (`/Span /ActualText`; `--actual-text false`
  restores the bare 1.8.0 runs):
  ```bash
  pdfnative render -i letter.json -o letter.pdf --direction auto \
    --font ar --font he --font latin --lang ar,he,latin
  pdfnative extract-text -i letter.pdf --format ndjson
  ```
- **32 Unicode scripts** — `--font gu|pa|kn|ml|or` add Gujarati, Gurmukhi (Punjabi),
  Kannada, Malayalam and Odia (36 bundled font modules); `doctor` probes them all.
- **Spot colours, the dual claim, JPEG 2000** — declare inks in `layout.print.spotColours`
  and paint with `{ "spot": "…" }`, `{ spot, tint }` or `{ inks }` (`/Separation`,
  `/DeviceN`); claim **PDF/A-2b or 2u and PDF/X-4 in one file** (`--tagged pdfa2b --pdfx
  pdfx4`, verified by `inspect --check pdfa,pdfx`); embed `.jp2` / `.j2k` images and
  watermarks untouched as `/JPXDecode`.
- **Refusals instead of silence** — `extract-text` / `compare --on-stream-error
  limit|throw|skip`: a content or font stream past `--max-inflate-size` is `E_INPUT` by
  default, never a silently empty page; `--variant table` refuses a malformed `PdfParams`
  with `E_INPUT` instead of an engine `TypeError`.
- **PAdES B-LT without a network** — `ltv embed --cert <pem|der> --ocsp <der> --crl <der>
  --match all|chain` composes `/DSS` + `/VRI` from material you already hold.
- **A compatibility promise, proved** — every command, flag, error code, exit code, `schema`
  subject and envelope field of 1.x is kept; the v1.5.0 test suite and its `schema manifest`
  / `status` / `list` captures run against the current sources on every pull request
  (`compat-previous`), and SECURITY.md states the policy and the supported runtimes.
- **CI/CD aligned with pdfnative 1.9.0** — the gate required on Ubuntu (Node 22, 24),
  Windows and macOS; `workflow lint` (zizmor + actionlint); CodeQL `security-extended` with
  the `actions` language; `publish.yml` as guard → build → publish → attest (an npm client
  pinned by SHA-512, the registry bytes attested, SLSA Build L2); ClusterFuzzLite over nine
  parser targets; Dependabot with a cooldown; the repository normalised to LF.

## What's new

### render

- `--direction auto|ltr|rtl` → `layout.direction` (full UAX #9, pdfnative 1.9.0); a
  paragraph block's own `direction` wins. `--actual-text [true|false]` → `layout.actualText`:
  untagged shaped and right-to-left runs carry `/Span /ActualText` with their logical text.
  The envelope carries `direction` and, only when switched off, `actualText: false`.
- `--font` / `--lang`: `gu`, `pa`, `kn`, `ml`, `or` (36 bundled font modules / 32 scripts);
  `tests/helpers/script-text.ts` carries a shaping probe per script (Kannada vowel sign
  before the subjoined consonant, the legacy Malayalam chillu spelling, a Malayalam split
  vowel, an Odia danda, a Khmer two-part vowel, a Myanmar e-vowel, …).
- Spot colours (JSON-only): `layout.print.spotColours: [{ name, alternate }]`; colour values
  `{ spot }`, `{ spot, tint }`, `{ inks: { name: tint } }` on text, tables and charts
  (`series[].colors` per value; a series `label` is optional). The engine's `Spot colour …`
  and `Ink mix …` refusals are `E_INPUT` (`INPUT_ERROR_PREFIXES`).
- The PDF/A-2 + PDF/X-4 dual claim: the CLI pre-check that refused `--pdfx` with `--tagged`
  is gone; `--tagged pdfa2b|pdfa2u --pdfx pdfx4 --output-intent-icc <cmyk.icc>` writes two
  OutputIntents and both identifications in the XMP; `pdfa1b` / `pdfa3b` with `--pdfx` are
  refused by the engine (`E_INPUT`). The envelope carries `tagged`.
- JPEG 2000: `image` blocks and `--watermark-image` accept `.jp2` (incl. RGBA →
  `/SMaskInData 1`) and `.j2k` bytes, sniffed by the engine, embedded as `/JPXDecode`
  (PDF 1.5).
- Four diagnostics under `--strict` / in `diagnostics[]`: `PDFA_GLYPH_WITHOUT_UNICODE`,
  `PDFA1_JPX_IMAGE`, `PDFA_JPX_IMAGE`, `TEXT_GLYPH_NOT_COVERED` (13 diagnostic codes, each
  with a trigger in `tests/helpers/diagnostic-triggers.ts`).
- `--variant table` refuses a `PdfParams` whose `infoItems` are not `{ label, value }`
  objects or whose rows carry no `cells` (`E_INPUT`); `schema render` documents the shape.
- Inherited from 1.9.0 and pinned by tests: a 160-entry table of contents paginates
  (`--inspect-layout` agrees), a chart series without `label` renders as `Series N`, lean
  and compact subsets under the six-letter tag, one text object per line, a transparency
  group only where needed, `/Scope` / `/Headers` / `/IDTree` on tagged tables.

### extract-text / compare

- `--on-stream-error limit|throw|skip` — pdfnative 1.9.0 reports a content or font stream
  past `--max-inflate-size` (`PdfStreamLimitError`, code `PDF_STREAM_LIMIT`) instead of
  returning the page without its text. `limit` (default) fails with `E_INPUT` naming both
  remedies, `throw` fails on any undecodable stream, `skip` reads the page as empty text
  (the 1.8.0 lenience). The error is classified by instance (`mapPdfError`), never by its
  message; `compare` applies the policy to both PDFs and never reports an unreadable page as
  equal.
- Untagged shaped and right-to-left text comes back in logical order, as typed; `subs` /
  `sups` glyphs extract as their source characters.

### ltv

- `ltv embed --cert <file> --ocsp <file> --crl <file>` (repeatable; PEM bundles split by
  `splitPemBlocks`, raw DER accepted, 16 MiB cap each) and `--match all|chain` compose the
  `/DSS` + `/VRI` through the engine's `composeLtvData` (`ocspResponseMatchesCertificate`
  decides what each VRI references; `all` references every item from every VRI, `chain` only
  what validates each signature, unmatched material still ships in `/DSS`). `--data` and the
  material flags are exclusive (exit 2); a `composeLtvData` refusal is `E_INPUT`;
  `--dry-run` composes without writing; the envelope carries `match`. The PAdES ladder gains
  an offline B-LT rung (`samples/sign/11-ltv-offline.*`).

### annotate / inspect / compare

- `annotate` type `link` is `buildAnnotationBody({ type: 'link', rect, url })` — the engine
  builds the `/Link` + `/URI` dictionary; the CLI's own builder is gone.
- `inspect --check` takes a comma list as well as the repeated form (`--check pdfa,pdfx`
  verifies the dual claim in one flag; a trailing comma is a usage error).
- `inspect` and `compare` decode `/Info` strings through the engine's `decodePdfTextString`
  (PDFDocEncoding — U+2022 for 0x80, U+2026 for 0x83 — and UTF-16); `src/utils/pdftext.ts`
  is deleted.

### Agent surface

- `schema status` pins `tagged`, `direction`, `actualText`, `match`; `schema render`
  describes `direction`, `actualText`, `print.spotColours`, the spot and ink colour values,
  JPEG 2000 and the dual claim, and the table-variant shape; `schema status` lists the 13
  diagnostic codes, `schema render` the 32 scripts. Completions carry every new flag.
- `docs/AGENT_CONTRACT.md` documents the stream-limit policy, logical-order extraction, the
  offline LTV rung and the compatibility promise; `llms.txt` carries the new flags.

## Compatibility

- **100 % backward-compatible command surface** — no flag, default, exit code or error code
  changed; every envelope field is additive and pinned by `schema status`. 21 commands,
  19 subjects, 12 codes, 10 global flags; `render` 57 → 59 flags, `extract-text` 9 → 10,
  `compare` 8 → 9, `ltv` 7 → 11; the 14 manifest commands are unchanged.
  `tests/tools/manifest-compat.test.ts` holds the v1.5.0 captures to it.
- **Compatibility ledger** — C1–C4 are the behaviour changes the v1.5.0 test suite could not
  pass (`tests/compat/allow-1.5.0.json`), each inherited from pdfnative 1.9.0; C5 and C6 are
  repository-side changes, held by the sample baseline and by the CLI's own guard:
  - **C1 — the dual claim.** `--pdfx pdfx4` with `--tagged pdfa2b|pdfa2u` is accepted (two
    OutputIntents, both identifications); the single 1.8.0 message that refused the pair is
    replaced by two level-specific ones for `pdfa1b` and `pdfa3b` (engine ledger C14), still
    `E_INPUT`. The CLI usage error (exit 2) is gone.
  - **C2 — the stream limit.** A content or font stream past `--max-inflate-size` makes
    `extract-text` and `compare` fail with `E_INPUT` where 1.5.0 answered `ok` with an empty
    page; `--on-stream-error skip` restores the old answer. The error class reaches every
    command that opens a PDF: an object, cross-reference or content stream past the cap was
    `E_PARSE` in 1.5.0 (the engine's bare inflate error) and is `E_INPUT` now, with a message
    naming `--max-inflate-size`; `verify` keeps its own `E_PARSE`.
  - **C3 — logical-order extraction.** Untagged reordered, shaped and right-to-left runs
    extract as their source text (engine C20, C27); a `subs` / `sups` glyph extracts as its
    source character (the encoded code point wins). The 1.5.0 `it.fails` markers for Khmer,
    Myanmar and CJK extraction are gone; one Thai pair stays (see Notes).
  - **C4 — the inventory.** 36 font modules / 32 scripts (was 31 / 27) and 13 diagnostic
    codes (was 9): `doctor`, the `--font` allow-list error, `schema render` and the built
    binary's report say the new numbers. Additive.
  - **C5 — LF.** `samples/render/attachments/invoice.xml` is embedded byte for byte and is
    now LF like every tracked text file, so `attachments/01-pdfa3-with-xml.pdf` re-anchors.
  - **C6 — the table-variant shape.** `render --variant table` with `infoItems` given as plain
    strings rendered `undefined :` labels in 1.5.0; 1.6.0 refuses the document with `E_INPUT`
    naming the `{ label, value }` shape (a CLI guard — see Fixed and Upgrade).
- **Inherited pdfnative 1.9.0 byte-level changes** (one rebaseline, 46 of the 91 entries
  re-anchored, 8 added — `tests/regression/baselines/samples.sha256.json`, `since: 1.6.0`):
  every sample embedding a font (lean, compact subsets under the six-letter `ABCDEF+` tag —
  withheld under PDF/A-1; engine C6, C21, C28), every untagged document with shaped or
  right-to-left text (`/Span /ActualText`; C20, C27), every shaped run (one text object per
  line; C25), the watermark samples (a page transparency group; C11), the tagged documents
  (table semantics `/Scope`, `/Headers`, `/IDTree`; C12), `annotate/linked.pdf` (the engine's
  `/Link` body), the encrypted and signed samples (semantic fingerprints, whose decrypted
  content carries the new subsets), `attachments/01-pdfa3-with-xml.pdf` (C5) and
  `table-variant/01-financial-transactions.pdf` (`infoItems` as `{ label, value }`). Every
  PDF with an embedded font therefore differs byte-wise from 1.5.0 output while staying
  spec-valid; a consumer that hashed 1.5.0 output rebaselines once and keeps pinning with
  `--creation-date`.
- `tests/compat/allow-1.5.0.json` also excludes the repository-tree suites (`tests/tools/`,
  `tests/docs/`, `tests/regression/`) and `tests/utils/pdftext.test.ts` (the decoder moved to
  the engine; `inspect` and `compare` behave the same). 67 files and 839 cases of the v1.5.0
  suite pass against the current sources.
- Encrypted output is never byte-reproducible; a signed file's incremental revision carries
  a per-revision `/ID` (upstream — see Notes).

## Security

- **CodeQL `js/insecure-randomness` (#16, #17)** — the tests' temp-file names drew their
  entropy from `Math.random()`, which CodeQL traced into the owner password a command
  received; one `tmpName()` on `randomUUID()` in `tests/helpers/cli-harness.ts`, every
  suite uses it, the workflows test refuses `Math.random` in the tree.
- **CodeQL `security-extended`, first run on the release pull request** — two findings,
  both fixed at the source. `js/file-system-race`: `readBinaryFileCapped` sized a file with
  `stat()` and then re-opened it by path; it now opens one descriptor, takes the size from it
  and reads at most that many bytes (a file swapped or grown after the check still lands
  capped). `js/insecure-temporary-file`: the suites created files with guessable names
  straight under `os.tmpdir()`, a flow CodeQL followed into `writeOutput`; every temp file now
  comes from `tmpName()` (a private `mkdtemp` directory, mode 0700, removed at exit, the
  extension kept) or from a `mkdtemp` directory of the suite's own — no
  `path.join(os.tmpdir(), …)` is left in `tests/`.
- **Dependency Review licence allow-list** — the ClusterFuzzLite engine lockfile
  (`.clusterfuzzlite/engine/package-lock.json`, never in the package) carries five
  BlueOak-1.0.0 packages (`tar`, `minipass`, `yallist`, `chownr`, `isexe`) and the CC-BY-4.0
  `caniuse-lite` table; both licences are allow-listed with the reason in
  `dependency-review.yml` (BlueOak-1.0.0 is OSI-approved and permissive; CC-BY-4.0 covers
  data, not code).
- **Scorecard** — `codeql.yml` holds `security-events: write` at job level only (#2); the
  publish job installs no npm client from a floating tag (#15: the client is pinned by the
  SHA-512 of its registry tarball); the `attest` job's `contents: write` and its
  `npm install pdfnative-cli@<exact>` into a throwaway project are deliberate and documented
  in SECURITY.md (#14); fuzzing (#7) is covered by ClusterFuzzLite; the single-maintainer
  review finding (#3) and the Best Practices badge (#5) are acknowledged in SECURITY.md.
- **Dependabot alerts 18–26** (source-map-js, brace-expansion, vite via vitest,
  `@vitest/mocker`) — all development scope, none shipped; closed by the toolchain bumps
  (vitest 4.1.12, vite 8.3.5, brace-expansion 1.1.21 / 5.0.12, source-map-js 1.2.2). The
  remaining moderate advisory (minimatch < 11.0.1, GHSA-g3hv-75wg-m249) has no fix inside
  the eslint 9 / typescript-eslint 8 lines; `npm audit --audit-level=high` is clean.
- **Inherited engine fixes**, held by `tests/fuzz/`: CWE-835 (a stray `)`, `{` or `}` no
  longer spins the tokenizer — `pdf-bytes.test.ts`), CWE-125 (`parseFontData` is
  bounds-checked on a truncated font — `fonts.test.ts`), CWE-682 (SHA-256 / SHA-512 of
  inputs ≥ 512 MiB; the CLI signs through `node:crypto` by default and the pure path is the
  engine's — `engine-surface.json` waives it as tested upstream).
- **Supply chain** — guard → build → publish → attest with digests end to end; every
  action resolved to one SHA across the tree; zizmor and actionlint on every pull request;
  harden-runner on every job (block mode where the endpoints are known, audit with a dated
  reason elsewhere); SBOMs (CycloneDX, SPDX, toolchain) and the Sigstore bundle on the
  release; `fuzz/` and `.clusterfuzzlite/` never in the package (`files` is held to it).
- **Bounded offline material** — `ltv embed --cert/--ocsp/--crl` files are capped at 16 MiB
  each and parsed by the engine; nothing is fetched.

## Notes

- `inspect --check pdfx` uses pdfnative's structural validator — validation evidence, not a
  certified preflight. PDF/A-2b|2u and PDF/X-4 can now be claimed by the same file; PDF/A-1b
  and PDF/A-3b cannot.
- veraPDF 1.30.2 accepts a JPEG 2000 image under a PDF/A-1b claim (its PDF/A-1 profile has no
  rule against a PDF 1.5 filter), so the corpus carries no such negative canary; the engine's
  `PDFA1_JPX_IMAGE` diagnostic — and `--strict` — is the guard, held by the diagnostics suite.
- **Upstream limits recorded in ROADMAP.md**: `metadata` rewrites the XMP without the
  PDF/X identification (re-check after editing); signed output carries a per-revision `/ID`
  drawn at signing time (signed samples are fingerprinted semantically); PDF/X-1a / -3 / -4p
  are not exposed by the engine (spot colours are); hyphenation dictionaries from the CLI are
  deferred by posture; a Thai above-vowel + tone-mark pair (`ตั้ง`) still extracts in
  geometric order from untagged output (`it.fails` `thToneBelow`; tagged output is exact);
  the synthetic Gray profile builder has no `version` option (the PDF/A-1 canary patches the
  header byte). Issue drafts for the maintainer are under `.github/drafts/`.
- `--on-stream-error limit` is the right default for untrusted input: a document that cannot
  be read is reported, and `compare` never calls two documents equal because a page was
  skipped. Raise `--max-inflate-size` for a trusted large file instead of passing `skip`.
- `--actual-text false` exists for byte-for-byte parity with 1.8.0 renders of untagged
  shaped text; it removes the logical-order guarantee of `extract-text` on that file.
- `ltv embed --match all` is the Adobe-tolerant superset (every item in every VRI);
  `--match chain` is the minimal, standards-exact form. Material that matches no signature
  is `E_INPUT`, not silently dropped.
- Under `--json`, stderr may carry warning lines before the envelope: the envelope is always
  the LAST line (`--quiet` drops the rest) — see AGENT_CONTRACT §1.
- The Windows and macOS legs, `workflow lint`, CodeQL's `actions` scan, `fuzz.yml` and
  `node-current.yml` run for the first time on this release's pull request; the ruleset with
  the seven required contexts is imported by the maintainer after that first green run.

## Upgrade

No action required from 1.x — all existing invocations behave identically on Node ≥ 22,
with two reportable differences inherited from the engine: `extract-text` / `compare` fail
with `E_INPUT` on a stream past `--max-inflate-size` (pass `--on-stream-error skip` for the
1.5.0 answer, or raise the cap), and `--pdfx pdfx4` with `--tagged pdfa2b|pdfa2u` now
succeeds where it was a usage error (ledger C1, C2).
Hash-based consumers: 1.9.0 changes the bytes of every PDF that embeds a font (lean, compact,
tagged subsets), of every untagged document with shaped or right-to-left text and of every
watermarked or tagged document — rebaseline once, then keep pinning with `--creation-date` /
`SOURCE_DATE_EPOCH`.
Sample baseline: one rebaseline, declared — 46 of the 91 entries re-anchored to `since:
1.6.0` (the groups listed under Compatibility) and 8 added (`chart/06-per-bar-colours`,
`images/01-jpeg2000`, `multilang/12-five-indic-scripts`, `multilang/13-rtl-direction`,
`print/08-spot-colours`, `print/09-dual-pdfa2b-pdfx4`, `sign/rsa-pkcs7-ltv-offline`,
`toc/02-long-toc`); 45 entries keep their 1.5.0 reference. The conformance corpus grows from
22 to 25 files (`pdfx4-spot-colours`, `dual-pdfa2b-pdfx4`, `jpx-pdfa2b`).
`samples/render/table-variant/01-financial-transactions.json` carries `infoItems` as
`{ label, value }` objects — the shape the engine types; a document with plain strings there
now fails with `E_INPUT` instead of an engine `TypeError`.
